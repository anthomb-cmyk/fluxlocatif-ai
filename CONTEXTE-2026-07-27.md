## 6. Accès et environnement

### Lancer l'application en local

```bash
cd /Users/anthonymakeen/fluxlocatif-work && set -a && . ./.env && set +a && PORT=3100 node server.js
```

Puis `http://localhost:3100/client.html`.

Le fichier `.env` **existe déjà**, il est ignoré par git et contient
`SUPABASE_URL` et `SUPABASE_SERVICE_ROLE_KEY`. La clé `service_role` donne un
accès complet à la base: elle ne doit jamais être copiée ailleurs, ni écrite
dans un message, ni commitée. Si elle manque, le serveur refuse de démarrer,
c'est volontaire.

**Le serveur local lit et écrit la vraie base de production.** Il n'existe pas
de base de test. Sauvegarder avant toute modification de données.

### Se connecter au portail sans mot de passe

Ne jamais saisir de mot de passe ni créer de compte. La méthode employée toute
la journée: générer un jeton par l'API d'administration, puis l'échanger dans la
page.

```bash
cd /Users/anthonymakeen/fluxlocatif-work && set -a && . ./.env && set +a && node --input-type=module -e '
import { createClient } from "@supabase/supabase-js";
const a = createClient(process.env.SUPABASE_URL, process.env.SUPABASE_SERVICE_ROLE_KEY, {auth:{persistSession:false}});
const { data } = await a.auth.admin.generateLink({ type:"magiclink", email:"anthonymakeen+test@gmail.com" });
console.log(data.properties.hashed_token);'
```

Puis dans la console de la page:

```js
window.supabase
  .createClient("https://nuuzkvgyolxbawvqyugu.supabase.co", "sb_publishable_103-rw3MwM7k2xUeMMUodg_fRr9vUD4")
  .auth.verifyOtp({ type: "magiclink", token_hash: "LE_JETON" })
```

Le jeton est à usage unique, il faut en générer un nouveau à chaque fois.

**Attention:** `anthonymakeen@gmail.com` est un compte **employé**, il est éjecté
du portail client vers `/employee`. Seul `anthonymakeen+test@gmail.com` a le rôle
`client` rattaché à `client_elevate`.

Si une session employé est déjà ouverte dans Chrome et qu'il faut la préserver,
sauvegarder `localStorage["sb-nuuzkvgyolxbawvqyugu-auth-token"]` dans
`sessionStorage` avant d'ouvrir la session client, puis le remettre après.

## 7. Les données

Supabase, projet **`nuuzkvgyolxbawvqyugu`** (FluxLocatif). Ne pas le confondre
avec `mkgkrfcfhtrlecfuzroz`, qui est le CRM Socle, un autre produit.

Les données ne sont pas dans des tables classiques mais dans des documents JSON
d'une table `kv_store`, une ligne par fichier. C'est un choix imposé par le
disque éphémère de Railway, qui effaçait tout à chaque déploiement.

| Clé | Contenu |
| --- | --- |
| `clients.json` | Clients propriétaires et leurs critères |
| `listings.json` | Logements, clés de la forme `L-1008` |
| `candidates.json` | Dossiers de candidats, 28 réels |

Trois clients existent: `client_demo`, `client_elevate`, `client_riviere`.
ELEVATE a 20 logements et **zéro candidature**.

Pièges connus:

- Les clés de `listings.json` sont `L-1008`, mais `normalizeRef` retire le
  préfixe. La fonction `trouverCleLogement` résout les deux formes.
- Le nom d'un candidat peut être dans `nom`, `name`, `full_name`, ou
  `prenom` + `nom_famille` selon l'époque du formulaire. Le serveur calcule
  `candidate_name` au moment de servir.
- Le numéro d'unité des logements n'a pas de champ dédié: il est dans les notes,
  sous la forme « Unité #1. ». Le portail le lit de là, sans écrire en base.

Lecture type:

```bash
cd /Users/anthonymakeen/fluxlocatif-work && set -a && . ./.env && set +a && node --input-type=module -e '
import { createClient } from "@supabase/supabase-js";
const a = createClient(process.env.SUPABASE_URL, process.env.SUPABASE_SERVICE_ROLE_KEY, {auth:{persistSession:false}});
const { data } = await a.from("kv_store").select("value").eq("key","listings.json").maybeSingle();
console.log(Object.keys(data.value).length);'
```
